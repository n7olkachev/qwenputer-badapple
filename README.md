# Bad Apple!! on the Qwenputer

Bad Apple!! played by the RISC-V CPU that lives inside Qwen3.5-4B's weights.

[Qwenputer](https://github.com/divagr18/qwenputer) is Qwen3.5-4B with a 32-bit RISC-V CPU
compiled into 11 extra transformer layers, using the model's Gated DeltaNet state as RAM. Its
execution is visible in the token stream: every instruction becomes a few *trace tokens*, and
`putchar` is one `BYTE` token. So if the CPU decodes a video and prints the pixels, **the
model's output token stream is the video**.

This repo puts the whole of Bad Apple!! (3:39, 80×60, 1-bit, 12 fps) into the machine's
memory map and plays it:

| | |
| --- | --- |
| Frames | 2,629 × 80×60 @ 12 fps (the whole 3:39) |
| Compressed video | 250,143 bytes ([ZX0](https://github.com/einar-saukas/ZX0), 6656-byte window), 6.3× |
| Where it lives | 131,072 bytes in the DROM (`.rodata`) + 119,080 bytes in **ROM as `lui` immediates** |
| Decoder | ~1.5 KB of C, 26 KB of RAM (a ring of words) |
| Cost | 17,147,091 RISC-V instructions, 19,059,752 trace tokens (~7,250 per frame, ~12 per pixel-byte) |
| Output | 1,577,400 `BYTE` tokens, one per 8 pixels, byte-exact |

## Verification

| Where it ran | What | Result |
| --- | --- | --- |

| The compiled circuit (`fastexec.FreeRun`, free-running, every token generated by the circuit) | frames 0–12, 28,000 tokens | every token = reference, bytes = video ([results/circuit_0.json](results/circuit_0.json)) |
| The compiled circuit, snapshotted at frame 1390 (across the DROM → ROM-sled switch) | frames 1390–1396, 58,000 tokens | every token = reference, bytes = video ([results/circuit_1390.json](results/circuit_1390.json)) |
| Stock `Qwen3_5ForCausalLM` modules, bf16 (the chip layers as the merge emits them), teacher-forced prefill | 6,000 tokens at frame 0 and at frame 1390 | 0 inexact dims, 0 wrong predictions ([results/](results/)) |

Not done yet: a full-video run on the circuit, a GPU job (~19M tokens at 3–6K tokens/s ≈ 1–2 h on an
L4 / 5070 Ti; on an M1 CPU the executor does ~180 tokens/s). These runs used the computer layers
alone (chip-only, as the community Doom/CHIP-8 demos did); Qwen's chat layers were not involved.

## How it fits

The machine has 256 KB of code ROM, 128 KB of read-only data (DROM) and 32 KB of RAM. Even
zlib needs ~145 KB for a 64×48 version, so:

- **ZX0** (optimal-parsing LZ with Elias-gamma codes, built for 8-bit machines) compresses the
  packed 1-bit frames 6.3×; the decoder is ~40 lines of C.
- **ROM as data.** Loads from ROM fault (it holds pre-decoded instructions), but `lui rd, imm20`
  materializes 20 bits per 4-byte instruction. The sled is 2,977 blocks of 16 `lui` + `ret`:
  40 data bytes per 68 bytes of ROM. `stub.S` calls a block and dumps the 16 registers.
- **A ring of words.** A byte store (`SB`) costs 4 trace tokens on this machine, a word store
  1, so the match window holds one byte per word: 6656 words = 26 KB, the compressor's max
  offset. The copy loop is unrolled ×8: 3 tokens per pixel-byte (`lw`, `sw`, `ecall`).

`guest/badapple.c` is the decoder, `tools/encode.py` makes `drom.bin`, `sled.S` and `config.h`.

## Reproduce

```bash
brew install riscv64-elf-gcc ffmpeg yt-dlp          # macOS; any rv32 bare-metal gcc works
git clone --depth 1 https://github.com/divagr18/qwenputer
(cd qwenputer && git apply ../patches/fastexec-q-family.patch)
(cd qwenputer/experimental/riscv && uv sync --extra hf)
(cd third_party && git clone --depth 1 https://github.com/einar-saukas/ZX0 && cd ZX0/src && \
  sed 's/MAX_OFFSET_ZX0    32640/MAX_OFFSET_ZX0    6656/' zx0.c > zx0_6656.c && \
  cc -O2 -o zx0_6656 zx0_6656.c compress.c optimize.c memory.c)
yt-dlp -f 'bv*[height<=240]+ba/b[height<=240]' --merge-output-format mp4 -o video/badapple.mp4 \
  'https://www.youtube.com/watch?v=FtutLA63Cp8'

RUN="uv run --project qwenputer/experimental/riscv python"
$RUN tools/encode.py video/badapple.mp4 --size 80x60 --fps 12   # ~15 min (optimal parsing)
./guest/build.sh                                                # build/badapple.elf
$RUN tools/run_ref.py                                           # the whole video, ~1 min
$RUN tools/render.py --gif                                      # build/badapple_qwenputer.mp4
$RUN tools/run_circuit.py --frames 12                           # the circuit, CPU
$RUN tools/run_circuit.py --start-frame 1390 --frames 6         # across the ROM sled switch
$RUN tools/run_circuit.py --device cuda                         # the whole video, on a GPU
$RUN tools/run_hf.py --start-frame 0 --tokens 3000              # stock HF modules, bf16
```
